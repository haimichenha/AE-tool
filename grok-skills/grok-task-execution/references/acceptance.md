# 跨领域验收：同一循环，不同证据

| 任务 | Grok 可承担 | 宿主执行与验收 |
|---|---|---|
| 软件/自动化 | 分析调用链、生成补丁、复核测试结果 | 定向测试、构建、diff、回归、部署读回 |
| 文档/报告 | 结构、表达、逐项审阅 | 用实际工具生成文件，渲染并检查页数、内容、版式 |
| 数据处理 | 字段映射、分析方案、异常解释 | 原始数据校验、可重复计算、汇总对账、抽样核验 |
| 研究 | 基于提供来源归纳、识别争议 | 实际检索原始来源，核对时间、引文、链接与结论 |
| 运维 | 诊断假设、可回退操作方案 | 授权范围内命令、服务状态/日志、备份和回退验证 |
| 本地软件汉化 | 翻译、术语统一、静态证据审阅 | 构建原生文件、哈希/标识校验、真实宿主启动与功能测试 |

不能声称无工具的 Grok 调用已经看过网页、操作过 GUI 或执行了命令。工具不可用时换成有证据的待办/人工验收，不虚构完成。

外部发送、付款、不可逆删除、生产部署需要当前动作的明确授权；已有任务卡不扩大权限。硬件上电、人工观察或 GUI 交互不能通过多问模型来替代。

跨任务续跑时保留目标、证据、产物、授权边界、待办与失败原因；不要把某次 DLL 的固定偏移、机器路径、编码或词表提升成通用规则。
