# Grok 通用持续执行

这是**宿主监督的技能**：Grok 产出分析、草稿和操作建议；宿主使用获准的工具真正执行并验收。不是后台常驻服务，不承诺关闭会话后继续运行，也不把建议冒充已执行结果。

## 入口与准备

1. 先读目标仓库 `AGENTS.md`、入口技能和当前任务状态。明确目标根目录，不使用 IDE 无关活动文件推断范围。专业任务由专业技能定义验收，通用技能只管理过程。
2. 列出可独立验收的小任务、依赖、允许写入/外传范围、可观察标准、模型、端点及停止上限。使用 [任务卡与回执](references/contracts.md)；跨领域验收参考 [验收边界](references/acceptance.md)。
3. 凭据只从本机既有设置解析，不写入任务卡/Git/日志。改变任务不自动继承先前数据外传授权。端点和资料范围不明确时先询问；可先完成不需外传的本地工作。
4. 标准库账本需要 Python 3.10+。可选网络适配器需要 PowerShell 7、已配置的 Claude CLI，以及相邻安装的 `grok-software-execution/scripts/grok-common.ps1`。必须显式传入所选 Grok 模型，不能沿用旧 runner 的 Claude 默认值，不能因超时换模型或端点。

## 持续循环（每轮都实际做下一步）

账本工具：`scripts/task_state.py --state <绝对路径/state.json> <命令>`。

1. 首次 `init --card <task-card.json>`；续跑只执行 `next`，不清空旧状态、不重新初始化。
2. 对 `ready` 项先 `begin --task <id> --phase work|verify`。写入开始标记**后**才调用 Grok 或执行动作；必须检查 begin 返回成功；一个 begin 只对应一次有界工作/一次模型调用。
3. 构造小型、已获准外传的证据 JSON。可用 `scripts/invoke-grok-step.ps1` 请求 Grok：它禁用执行工具，只传显式 JSON，不扫描整仓库。每次调用用全新输出目录；没有内置重试。
4. **work**：审核 Grok 的译文/计划/草稿/代码，再由宿主在允许范围执行。先备份和检查前置条件；记录真实命令、退出码、产物哈希和未完成项。`ReadOnly` 工作不修改目标。写操作不确定是否完成时不能直接重放。
5. **verify**：用动作完成后重新读取的证据，进行独立测试/渲染/计算/来源核验；需要时让 Grok 只读复核。模型说“通过”不是测试执行证据。宿主构造回执，`record --receipt <receipt.json>`。阶段 work 不能直接标为 done。
6. 再执行 `next`，继续可执行任务，**不要每完成一个子任务就停下来等用户说继续**。依赖被阻塞时先做其他独立任务，不擅自删除困难验收项。

## 有效推进，而不是重复调用

- 先把用户目标拆成可观察的验收项。每一步写清：对应哪一项、尚缺什么、为什么现在执行这个动作、预期得到什么证据。
- 根据读回结果选择下一步：缺信息→定向读取/查询；定位问题→针对性修改；已有候选→测试/渲染/对账；验收通过→下一个未完成项。
- 不是要求每次命令字符串不同。没有新条件的重复操作不算进展；换工具、换命令名、重写记忆、重述结论也不算进展。
- 新账本version=2要求 `progress`：产物变化、新证据、实际验证或定位阻塞，并引用真实证据；同一阶段性质下重复使用相同证据哈希不能冒充新进展。语义关联仍须宿主审核，不能用改时间戳/改日志格式刷进度。
- 合理重试必须注明条件变化或瞬时故障依据，并受原有次数/时间限制。测试命令可以重复，但要说明代码/输入/环境的变化，或为什么需要有界重复观测。
- 无进展时先调整假设或选择独立未完成项，不把“持续执行”变成无期限空转。防重复Write hook是最后的止损，不替代目标与证据驱动的工作流。

## 中断、失败、权限与预算

- `reconcile_required`：先确认原进程是否仍在运行，再读实际文件/服务状态。把读回证据补成该次回执；已应用动作进入 verify，未知状态记 blocked，确定未发生副作用才允许 retry。不要因 JSON/网络错误重复部署、提交、发送或支付。
- work 与 verify 次数**分开计数**。最后一次 work 成功仍能进入 verify（整体步数/时间也必须留出验收额度）。这是旧软件 runner 共用 ACTION/VERIFY 重试计数问题的控制层规避，不声称旧 runner 已被修复。
- 权限拒绝、认证失败、错误端点、证据污染或不可逆风险：停止该操作，不更换会话/路径/模型绕过。其他安全、无依赖工作可继续。
- `paused_limit`：保存进度后报告未完成项，不谎称完成。只有用户同意扩展范围或预算后才能建立引用旧状态的新任务卡。`blocked` 解锁同理，不偷改 ledger 清空失败次数。
- 账本记录的是有界步骤，不是账单计费器。适配器 `MaxBudgetUsd` 是单次 CLI 上限；不得将其宣称为网关实际计费硬上限。总调用数、总时间和每次额度都应在开始前受控。
- 工具锁文件表示另一个控制器可能活跃。中断留下 `.lock` 时，确认其中 PID 已退出并保留现场后才移除；不要并行写同一个账本。

## Claude 原生执行结果必须二次判定

真实模拟发现：hook停止回合后，Claude可能仍返回 `subtype=success`、`is_error=false`，但 `result` 为空。不能据此标记任务完成。模型自己的测试也可能漏掉需求。

用 `scripts/classify-claude-run.py --stream <stream.jsonl> --host-verification <host-verification.json>` 分开判定CLI结束与目标验收。宿主验证文件须来自实际独立检查，包含reviewer=host、exit_code、protected_inputs_unchanged、required_criteria列表和criteria逐项passed/failed结果；不得直接使用Grok自述。返回2表示未接受，必须保留未完成项。

`blocked_no_progress` 不自动重放原动作；`failed_acceptance` 反馈具体失败标准，下一次仅允许有新诊断或修改方案的有界纠正。模型声明“完成”但固定验收仍失败时，绝不能改验收值来迎合模型。穷尽本轮次数后如实报告，不无限追加调用。

## 完成与保存

只有每个任务的全部标准有宿主审核的实际证据、且 remaining_work 为空才完成。报告分清 Grok 做了什么、宿主做了什么、用户实测了什么；单独列运行验收尚缺的部分。

保留词表/脚本/结果来源与可复现命令。原始素材、凭据、二进制和运行日志不因“持续执行”而自动上传。Git 提交、推送、部署和删除沿用用户实际授权范围。
