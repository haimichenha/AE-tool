# 软件任务中的职责与接入

## 保留什么，不重复造什么

| 层 | 负责 | 不代表 |
| --- | --- | --- |
| SS / 软件项目技能（可选） | 需求澄清、方案、代码导读、用户默认路径验收、学习 | 已执行外部模型或已部署 |
| 本技能 | 一次委派的任务卡、work/verify、次数/时间限制、中断对账 | 新的项目总状态或学习掌握度账本 |
| `invoke-grok-step.ps1` | 已批准模型/来源、显式 JSON 证据、一次无工具调用 | 模型已读取工程、调用 MCP 或操作网站 |
| 宿主 | 审查提议、获准修改、独立测试、部署读回 | 用户已认可最终视觉效果 |

SS/AS 不可用时仍可单独使用本技能，不引入强依赖。已有项目状态记录目标和已认可项；委派账本只记对应调用和证据路径，完成后由宿主把结果摘要带回原项目状态，不复制第二份进度/学习系统。

## 一个小任务怎么交接

先从项目验收中选一条可观察行为，带上入口/版本、必要调用链、允许变化与保护项、证据缺口。视觉任务应区分“资源已创建”“资源已接入”“默认操作下看得见”，不能让执行器以构建成功替代最终效果。

宿主可将其收敛为现有 request 字段：`task_id`、`phase`、`goal`、`criteria`、`evidence`、`feedback`。不发送密钥、完整对话、无关仓库或用户账号资料。验收由项目目标决定，不从旧测试或模型输出反推标准。

`work` 只返回提议；宿主实际应用后重新采证，再做 `verify`。网络调用失败时仍可做已获准的本地检查，但必须分清是谁提出、谁执行、谁验证。继续任务前先看已有产物和调用回执，避免重复计费。

## 工具发现不是资源枚举

MCP 的工具与资源是不同能力：`resources/list` 返回空，不证明该服务没有工具；也不能凭空假定存在名为 `file` 的服务。使用宿主实际暴露的工具名称/描述或该客户端的工具发现入口。没有文件读取工具时用已获准本地读取能力；没有搜索工具时如实说明，不伪造检索。

推荐适配器显式禁用 Claude 工具与 MCP，只分析传入证据。若需 Grok 自行搜索或改代码，属于另一种工具/数据授权范围，不能靠提示词声称此适配器已具备该能力。`grok-search`、本执行技能和 SS 的只读 MCP 不是同一个服务。

## 推荐入口与兼容边界

- 推荐：`task_state.py` + `invoke-grok-step.ps1`。一次调用、无内部重试、显式模型/批准 origin、输出目录不得覆盖。`transport_class=ok` 与 `contract_valid=true` 仍不是宿主验收。
- `transport_reason` 保留失败类别，`retry_action=stop` 表示停止当前路由，`host_review_required` 表示需对账和判断而不是自动重试。预算耗尽需要缩小工作或获得新的预算授权。
- `grok-software-execution` 三个旧 runner 仍有 `claude-sonnet-4-6` 默认模型，部分有自动预算阶梯、直接工具或目录证据收集。direct runner 还有独立的旧分类器。**没有在本轮全面修复，不作为默认路径。**
- `selftest/run-task-suite.ps1` 是历史联网验收脚本，含机器专属路径，会调用模型；不是本仓库的离线单元测试。
- 不自动安装、注册 MCP、修改 provider、提交、推送或部署。AE-tool 保留汉化模块；SS 是否另建仓库/并入需要单独决定，不能发布本地候选时顺带复制运行日志或配置。

从仓库根运行离线测试：

```powershell
python -B -m unittest discover -s grok-skills/grok-task-execution/tests -v
```

PowerShell 7 用于适配器模拟测试；`python-docx` 是部分文档测试的可选依赖。被跳过的测试须单列，不把它们算作通过。这里不证明远端模型当前可用或真实网页已修复。
