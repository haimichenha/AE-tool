# 多效果、多轮汉化工作流程

## 1. 接力与分组

从当前状态读取已验收效果和用户刚给出的反馈；现场读回 AEX、核心、manifest、运行进程再行动。用户说“继续／下一项”不应重新问已有信息；仅在缺少目标、关键触发操作、无法安全退出的工程或所需许可时询问。

按下列维度分组，而非仅按菜单相邻关系：
- 使用相同核心和依赖的效果；
- 同一类参数／布局；
- 是否有预设浏览器、Mocha、样式编辑器等额外调用；
- 更改核心会影响哪些已安装消费者。

允许在已明确范围内批量生成词表和候选。一次发布可以是一项或已验证的小组；共享核心、交互未测、已有实际失败时优先独立试点。试点通过后结合用户范围和其余证据再决定下一组，不强制每次重复确认。

2026-09-13 曾有“23 个入口＋4 个核心”安装被审核拒绝；这是该次操作边界，不是所有未来任务只能逐项。不得自动拆小命令完成同一个被拒绝操作。可继续不受阻的离线工作，或提出真正缩小风险范围、单独评估的方案。

## 2. 构建前契约

每个效果记录：原始显示名／matchName、AEX 哈希、核心哈希、基础及派生定义、映射范围、候选与备份位置、共用消费者、允许改动的字节范围。

定义搜索需处理 `GlowDist` → `Glow_Dist`、`ZGlow` → `Z_Glow` 和 `_Autogen`；静态找到定义仍不证明活跃绑定。原版资源和重定位资源可能并存，读取活跃 PE PiPL 资源，不全文件寻找第一个同名 tag。

标题与分组、按钮、下拉显示、悬停提示、弹窗分开盘点。能生成 title 并不表示全部 UI 已翻译。保存候选时保留表达式、参数顺序、默认值和枚举 token；分别检查 AEX 与核心，不能笼统说“全是文字，没有改代码”。

## 3. 验证门槛

1. **静态**：版本锁、预期字段、限定字节范围、PIPl/matchName/参数键/枚举/表达式；同源重复构建应一致。
2. **宿主**：独立项目中，从真实注册菜单添加；验证正确效果而非“重复上次效果”。记录菜单 ID、参数索引／名称／matchName／类型／默认值。
3. **组合**：除了各自单独测试，覆盖代表性的 A→B、B→A，插入完成后重新读取已有实例；只有单独通过无法证明共用核心安全。
4. **渲染**：相同素材、时刻、设置和保存工程，使用无损输出；实际核对完成标记、帧集合、形状／通道与像素，不把启动器退出码或一个 DONE 当成全批完成。
5. **交互**：预设打开、选择／应用返回、编辑器和 Mocha 单独记录。脚本 `addProperty` 和原生菜单自动化仍不覆盖所有鼠标添加路径。
6. **用户反馈**：保存对象、版本和反馈范围。“看起来正常”不扩写成所有按钮、位深、素材、Premiere 都验证通过。

任何一层出现新失败，就停止用旧通过结论推广。保留成功与失败窗口，改变一个有证据支持的变量；不同时换核心、入口、预设和 GPU 设置来猜。

## 4. 安装与回退

- 先公开说明共享宿主影响；确认 AE/PR/相关编辑器不占用目标。
- 备份原 AEX、要改的核心和 manifest，校验备份后才写入；候选生成成功不等于安装成功。
- 正式入口保留原 matchName。停用副本时移出全部扫描路径、保留校验过的备份；不要删除用户工程中的引用，旧副本工程需要单独迁移。
- 修改核心前列出所有正式消费者。复用已验收核心时，优先只接一个新 AEX，避免无必要的核心重建。
- 写回后验证目标、未批准变更的其他入口和依赖。没有对应哈希读回与成功报告，不说“已经替换”。
- 回退与变更范围相同；新增共享消费者后，旧整套回退可能不再安全。只撤销单个入口时不要降级其他效果使用的核心。
- 失败时保留准确状态；不能关闭用户未保存工程来完成回退。受阻的部署与仍可做的词表、检查、文档工作分开报告。

## 5. 发布技能与源码

技能入口只保留路由和关键约束；经验写入专题参考，当前安装状态只有一个入口。历史日志不反复追加“最新”状态，也不当成机器自动重放计划。

用户明确要求提交时：检查远端和未提交差异 → 精确暂存相关文件 → 检查依赖和链接 → 测试 → 审阅暂存内容和敏感数据 → 提交并验证推送。不要暂存整个工作树。

公开源码、映射、测试和最少摘要证据；厂商二进制、原始转储、用户项目／素材、凭据、包含本机私有路径的运行安装器不上传。摘要不能替代本地可回退的二进制备份。
